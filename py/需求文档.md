## 1 业务背景

### 1.1 医疗场景

设备持续产生患者相关影像（含 DICOM 及原始图等）。数据可能关联姓名、证件号、检查号等敏感信息，受医疗与个人信息保护相关制度约束。用户需要：

- 磁盘不满、检查不因存图失败中断  
- 关键影像按制度留存，可备份、可恢复、可审计  
- 对外导出或跨机构拷贝前可做隐私处理  
- 操作可追溯，满足院内检查与纠纷调阅  

### 1.2 工业视觉场景

产线 7×24 小时采集原图、NG 图、指纹等二进制大文件，写入并发高。用户需要：

- 用 SSD 中转削峰，避免直接打满归档盘导致丢帧、卡顿  
- 磁盘水位可控，防止满盘停线  
- 按项目/批次/NG 等保留策略管理生命周期  
- 质检原图与元数据可追溯、可导出复盘  

### 1.3 现有痛点（用户侧）

| 痛点 | 影响 |
|------|------|
| 高并发直写大容量慢盘 | 丢帧、采集卡顿、工位效率下降 |
| 无自动清理 | 磁盘爆满、设备停机、诊室/产线中断 |
| 无可靠自动备份 | 硬盘损坏导致影像或质检原图不可恢复 |
| 无完整操作记录 | 合规检查、事故复盘缺少依据 |
| 中转/归档/备份缺少统一策略 | 隐私与篡改风险、运维全靠人工 |
| 依赖人工值守 | 夜班与多工位难以盯盘 |

## 2 总体用户需求

1. **无人值守**：后台静默运行，自动完成监控、清理、中转迁移、按策略备份。  
2. **多存储分区独立管控**：至少区分 **SSD 中转、长期归档、本地备份、网络/NAS 备份**（可按现场裁剪启用）。  
3. **模式可切换**：医疗模式与工业模式，默认参数与强制项不同（如医疗更强调双备份、审计与脱敏相关能力）。  
4. **全配置化 + 可远程管理**：路径、阈值、周期、端口等可配；提供管理接口供内网平台对接。  
5. **高可用体验**：单盘离线、网络中断、单文件失败、库短暂不可用时以告警为主，**守护进程不整体退出**；重启后能接续未完成的中转/备份状态，避免业务文件无故丢失。  
6. **日志与审计分离**：普通运行日志可滚动；安全审计类记录长期保留、防随意清除，支撑合规抽查。  
7. **国产化与 Windows 双栈**：同一套需求在 Windows 与麒麟上均可部署使用。

## 4 通用功能需求

### 4.1 配置管理

1. 首次启动自动生成默认配置；缺字段用默认值补齐；格式错误时给出明确提示，**暂停相关业务任务但不崩溃**。  
2. 可配置项至少包括：归档路径、SSD 中转路径、各盘告警阈值、普通/NG（及医疗急诊纠纷类）留存天数、扫描间隔、备份开关、本地/NAS 备份路径与备份保留天数、中转容量上限、管理端口、运行模式（医疗/工业）等。  
3. 支持通过管理接口更新配置并尽快生效（用户感知为“改完可用”，不强制理解是否热加载实现细节）。  
4. 配置变更须记入审计：谁、何时、改了哪些项（变更前后对比）。  
5. 路径在 Windows、麒麟、NAS 共享下可配置且可访问；错误路径有明确告警。  
6. 医疗/工业模式一键切换后，加载该模式推荐默认策略，并提示哪些项在医疗模式下为强制启用。  

### 4.2 磁盘监控与预警

1. **分盘监控**：SSD 中转盘与归档盘（及用户启用的备份盘）分别统计容量与使用率，分别告警。  
2. **分级告警**：  
   - 接近阈值：预警，提示即将影响业务；  
   - 超过阈值：紧急告警，并可通知上层管理接口。  
3. 盘符/挂载变化、磁盘只读、离线：记录告警，进程继续；恢复后自动恢复监控。  
4. 提供查询接口：各存储角色、容量、使用率、是否在线。  
5. SSD 超过配置上限时：加速向归档迁移、抑制或限流新中转写入，并紧急告警，降低采图因中转盘满而失败的风险。  

### 4.3 文件生命周期清理

1. 按类型/标记区分留存：普通、NG、医疗急诊/纠纷/诉讼类、用户标记“永久保留”等；永久保留类**不参与自动删除**。  
2. 扫描周期可配；清理不得显著抢占采集写入带宽（用户感受：清理时采图仍稳定）。  
3. 清理范围与中转未完成迁移文件隔离：未完成归档的中转文件不因“过期规则”被误删。  
4. 删除前写审计：业务 ID/路径、项目、大小、时间、删除原因、操作来源（自动/手动/账号）。  
5. 支持受控的手动清理（按时间、项目、类型等）；高危操作二次确认并留痕。  
6. 可识别并清理明确无用的空文件、损坏占位文件，并单独记日志。  

### 4.4 备份管理

1. 总开关与检查周期可配；**同一自然日全量备份至多成功完整执行一轮**（避免重复占盘）。  
2. **本地 + NAS** 双路径：医疗模式默认要求双备份均可用才视为满足策略；工业模式允许仅本地。  
3. 备份包带时间戳，保持目录层级与必要元数据文件；过程有进度信息（总数、当前、百分比、当前文件）。  
4. 新备份成功后清理超期旧备份包，删除记审计。  
5. 单文件失败、NAS 短暂离线：记录错误，尽量继续其余文件；后续周期可重试。  
6. 支持手动触发全量备份，记录操作者与范围。  
7. 提供恢复能力需求：可将指定备份恢复到指定位置；恢复操作全审计（谁、何时、恢复哪些）。  

### 4.5 日志与审计

1. 控制台 + 文件；按日分割。  
2. **运行日志**可滚动保留（如近 7 天，可配）。  
3. **审计日志**独立存放，保留期限可配且医疗场景默认长期（如不少于制度要求的年限，产品默认给出明确下限并允许加严）；禁止普通清理任务删除审计日志。  
4. 级别区分：常规、预警、错误、审计。  
5. 覆盖：启动、监控、迁移、清理、备份、恢复、配置变更、管理访问、鉴权失败、异常。  
6. 支持导出日志/审计记录供检查；目录不可写时告警，不崩溃。  

### 4.6 业务元数据

1. 每个受管文件可记录：类型、项目、唯一标识、索引/帧号、是否 NG、路径、采集时间、大小、中转与备份状态等。  
2. 入库失败可重试；短时不可用时不丢业务侧可恢复的记录（用户要求：恢复后补齐）。  
3. 支持按项目、时间、NG、文件 ID 等查询与批量导出，用于复盘与溯源。  

### 4.7 管理接口与辅助

1. 能力包括：磁盘状态、告警查询、手动备份/受控清理、配置更新、日志导出、打开各业务目录等。  
2. “打开目录”在 Windows 与麒麟上均打开**配置的真实路径**。  
3. 医疗模式管理通道须加密传输（HTTPS）；禁止在医疗生产环境仅依赖明文管理口对外暴露。  
4. 接口须鉴权；失败与越权访问记审计。  

### 4.8 部署与运行形态

1. 交付 Windows 可运行包与麒麟 x86/ARM 可运行包，依赖最小化，便于现场安装。  
2. 默认无强制 GUI，后台运行，靠日志与接口管理。  
3. 支持开机自启（Windows 服务 / 麒麟 systemd 等用户可接受的方式）。  
4. 升级或重装时，配置、审计日志与备份路径中的数据不得被安装程序无提示清空（需明确安装策略说明）。

## 5 SSD 高速中转相关需求（用户结果）

1. 采集优先写入 SSD 中转目录，再异步进入归档盘，减轻归档盘瞬时压力，降低丢帧与卡顿。  
2. 迁移成功后删除 SSD 上对应临时文件；失败则标记并重试；多次失败进入审计/错误列表便于人工处理。  
3. 中转任务不得压过采集进程的磁盘体验；可限制并发与节奏。  
4. 超大文件可分片读写，避免内存占满导致工作站异常。  
5. 异常断电或进程重启后，能发现 SSD 残留未迁移文件并继续迁移，避免“文件在 SSD 上无人管”或无故重复归档混乱。  
6. 中转水位上限可配，超限加速迁出并告警、限制新写入。

## 6 医疗场景专项需求

### 6.1 隐私与标识

1. 对 DICOM 等可解析格式，支持识别常见患者标识字段；提供可配置策略，例如：  
   - **院内归档**：原件按制度留存；  
   - **对外导出 / 跨机构拷贝前**：先按策略脱敏或拦截未脱敏文件并告警。  
2. **科研等场景**：可配置为对外仅提供去标识数据，降低再识别风险。  
3. 未满足脱敏策略的外发应可阻断并记安全审计。  

### 6.2 保密性与完整性

1. 归档与备份数据支持静态加密；算法与密钥管理满足院内密码应用要求（如支持国密算法选项）；密钥不得写死在程序中，并支持轮换制度。  
2. 重要影像具备完整性校验信息；迁移/备份/恢复后可校验，失败则隔离并告警。  
3. 备份包在无授权情况下不可被普通方式随意浏览明文影像（用户目标：防拷贝泄密）。  

### 6.3 访问控制

1. 管理接口账号分级（如技师 / 管理员 / 仅脱敏访问等）。  
2. 删除、改配置、导出明文等按角色授权；高危操作二次确认。  
3. 备份存储访问受限（如网络侧仅授权主机），禁止匿名可读。  

### 6.4 留存与双副本

1. 医疗模式强制本地 + NAS（或院内认可的第二副本）策略可配置为强制，缺一则持续告警直至满足。  
2. 急诊、纠纷、诉讼等标记对象延长留存，自动清理不得删除；支持永久保留标记。  
3. 恢复操作全审计，恢复后完整性可再校验。  

### 6.5 传输

1. 向 NAS 或外部系统传输患者相关文件时使用加密通道。  
2. 生产环境管理与调阅接口使用 HTTPS。  

### 6.6 泄露溯源（可选增强）

1. 在制度允许范围内，支持对外发或关键副本增加可追溯标识（如隐写/可见水印策略由用户选择），用于泄密追溯；不得影响法定归档原件的合规性要求时，应允许“仅对外发副本加水印”。

## 7 工业视觉场景专项需求

1. 默认不强制患者级脱敏；可选产线/设备水印，抑制原图外流。  
2. 元数据绑定产线、设备、批次，支持按批次检索与导出。  
3. 强调 SSD 中转与磁盘预警，保障连续生产。  
4. 支持批次导出到可移动介质的受控流程，并记录操作者与范围；导出包可附带批次说明。  
5. NAS 备份可关，允许低成本仅本地备份。  

---

## 8 全局异常与连续性需求

1. 目录缺失可自动创建（在权限允许时）；权限不足则告警，其它任务继续。  
2. 单盘或 NAS 故障只暂停相关任务，其余监控/清理仍可用；恢复后自动续跑。  
3. 单文件失败不影响整轮任务目标（能备份的继续备，能迁的继续迁）。  
4. 监控、清理、备份、管理接口彼此故障隔离，主守护不因单模块失败而退出。  
5. 元数据服务短时不可用时有缓冲与恢复后补写，避免业务记录空洞。

## 9 性能与容量（用户可感知指标）

| 项目 | 需求 |
|------|------|
| 与采集共存 | 清理/迁移/备份进行时，采集写入无明显周期性卡死 |
| 目录规模 | 支持单目录海量小文件与大图混合的长期运行 |
| 日增量 | 支持每日数十 GB 量级素材的中转与按日备份策略 |
| 资源 | 常驻内存与 CPU 占用可控，不拖垮同机采集软件 |
| 连续运行 | 7×24 小时稳定运行，无因本软件导致的系统性内存只增不降 |

具体数值指标可在项目合同中按工位硬件再约定（如最大目录文件数、最大日增量）。

## 10 安全需求总表（跨模式）

1. 最小权限：只管理配置的路径。  
2. 管理入口鉴权与审计。  
3. 医疗模式下传输与对外接口加密。  
4. 审计日志防普通清理误删。  
5. 不默认向公网上传业务数据。  
6. 配置与密钥与程序分离。  

---

## 11 明确不在范围

- 不承担临床诊断、报告书写、完整 PACS/HIS 业务。  
- 不替代医院等级保护测评、等保整改与第三方审计结论。  
- 不保证任意加密盘、未知私有格式的深度解析。  
- 不提供未授权的数据恢复或对抗性“去水印”能力。  

---

## 12 验收标准（用户视角）

1. 连续运行约定时长（如 7 天）无崩溃、无因本软件导致采集持续丢帧。  
2. SSD 中转开启时，高并发写入下采图过程平稳可接受。  
3. 分盘水位到阈值可出现对应级别告警，记录可查。  
4. 过期清理、每日至多一次完整备份、旧备份清理行为与配置一致。  
5. 医疗模式：双备份策略、对外脱敏/拦截、加密与审计要求可演示通过。  
6. 断电或进程重启后，SSD 未完成迁移文件可续迁；不出现无策略的全量重复备份打满磁盘。  
7. 删除、备份、恢复、配置变更、导出等关键动作均有审计记录可导出。  
8. Windows 与麒麟（x86/ARM）均可完成安装、自启与基本功能验收。  
9. 管理接口在鉴权下可完成状态查询与授权操作；越权被拒绝并留痕。  

---

## 13 假设与依赖（写清责任边界）

1. 操作系统账号与磁盘 ACL、NAS 权限由用户环境配置。  
2. 时间准确（NTP）影响“按日备份”“留存天数”的正确性。  
3. DICOM 脱敏依赖可解析的标准字段；私有封装需另行约定。  
4. 合规年限、是否必须双活机房等，以用户制度与合同为准，本需求提供可配置能力加以支撑。

## 14 需求优先级建议（便于排期）

| 优先级 | 内容 |
|--------|------|
